# Sumgeon

A math-practice dungeon crawler. The player fights anthropomorphic monsters built from numbers and math symbols, and the answer to each problem is the damage dealt.

## Players and saving (patterned on sound-box-crosswords)
- `sumgeon:` holds the device's own data: `profiles` ([{ id, name }]), `profile` (who's playing), `storage` (version) and `device`.
- `sumgeon:@<id>:` holds one player's data. Every key saved there must be in `OWN_KEYS` in `store.js`, which throws on any other key.
- **Dungeon version** (`DUNGEON_VERSION` in `app.js`, saved per player as `dungeon`), while we're before release: bump it when a balance change means saved runs should start over (how fast heroes are freed, how strata open). On the next load each player's dungeon progress resets (`wings`, `bestiary`, `best`, and heroes back to just their own captain, via `resetTeam`), keeping their hero, chalk color and settings. What's been learned (`facts`) is kept too, unless the version is in `LEARNING_RESETS` (version 3: placement and skipping ahead changed how learning counts). Add a line to its list saying why. Version 5 is the grade strata: runs start over, learning is kept (no fact key changed meaning). Version 6 is the progression (paths, the window, chapters and mega bosses): runs start over at chapter 1, learning is kept, so a player's learned facts carry them along the path. **Locked since 2026-11-27: real players are using the game.** Don't bump it, and don't add to `LEARNING_RESETS`: a change must keep everyone's saved progress (map or migrate old data on load instead, as `OLD_BANDS` does).
- Storage version 2 moved the prototype's single `sumgeon` key into the `default` player, resumably.
- Names belong to the device. Remove only appears on a device with two or more players, never for the one playing, confirms with a second tap, and only affects this device.
- `wallet` (per player): money found in chests, in cents. Never lost, not even on a loss, and a dungeon-version reset keeps it.
- `achievements` (per player): `{ earned: { id: time first earned }, seen: [ids shown on a card] }` (`freshAchievements` in `achievements.js` cleans it on load). Never taken away, kept through a dungeon-version reset.
- `items` (per player): the inventory, `{ have: { id: count }, slots: [id or null] × 3 }` (`freshItems` in `loot.js` cleans it on load). Kept between runs and through a dungeon-version reset.
- `wardrobe.plush` (per player): the plushies owned (ids). Everyone has Pluffy (`freshWardrobe` adds it), since it sat on the start scene before the others came. Kept through a dungeon-version reset; synced as the record's `plush`, which only grows (RECORD_VERSION 4).
- **Leaving mid-run** (`autoPause`, `comeBack`, `settle` in `app.js`): the page hidden (visibilitychange, pagehide) mid-fight pauses as ⏸ does (no "Paused" line said to nobody), so coming back shows the pause card and Keep fighting resumes the same problem with its time. Mid-attack or mid-Hero-Moment it pauses as the next problem comes up (`G.pauseWanted`; a card shown is a stopping place already and clears it); mid-descent the descent ends at once (`skipDescent`) and the run pauses at its first problem. On hide and on coming back every finite animation is finished (`settle`), since iOS froze an iPad mid-transition (a dimmed screen, the monster, pad and hearts missing); coming back redraws the fight (`redrawFight`; not while the room waits empty after the descent, where it drew the first monster early) and the pause card fresh, and the start screen where it was scrolled to (it used to jump back to the top). The roar, the 💡 nudge and the dot flash's hide wait out the pause.
- **The run in progress** (`run`, per player; `saveRun`, `savedRun`, `checkRun`, `keepGoing` in `app.js`): iOS can reload a Home Screen app left in the background, so the run is saved as it goes: when each problem comes up, as an answer lands (`stage` "next", or "beaten" when it empties the monster's HP), when a floor's card shows ("floor": the next floor), and on pausing or leaving (the answer time so far). It holds the stratum, band, depth, each floor's monster by name (a cursed digit by digit, the boss by its form), the floor, HP and max, hearts, streak, solved and tries, stars so far, the retry and recent lists, the armed items (`fx`), the floor's trait state (charge count, half-HP, stars' lost hearts and slow answers, barks), the Legend's exam, the Hero Moments run state and the current problem (with whether its hint was open). It's in `LOCAL_KEYS` (never synced). A finished, lost or exited run clears it, and starting a new run drops it. On the start screen, one saved in the last 4 hours (`RUN_KEEP_MS`) that still fits the game (`checkRun`: its version, `DUNGEON_VERSION`, an open stratum, every monster and the fact key still known) is offered as a big **Keep going?** button (with where it was), and the first tap elsewhere says "Keep going? Tap the big button!"; it resumes at the problem it was on, without the descent. Anything that doesn't fit is dropped quietly, its armed items back in the bag.
- `told` (per player): how many times the voice has explained each thing (`{ tag: count }`, `once` in `app.js`), so explanations aren't repeated every time.
- Settings (`band`, `start`, `grade`, `sfx`, `voice`) are per player and save as they change in the menu. `ops` and `diff` are the prototype's, kept only so a player who practiced × or ÷ starts in 3rd grade. Bands saved before the grade strata (`sprout`, `balance`, `apprentice`) are mapped on load (`OLD_BANDS` in `wings.js`: `kinder`, `first`, `third`), and a player with a grade starts in that grade's stratum.

## Sound and voice
- `sfx.js` synthesizes every effect with Web Audio, on **the one Web Audio context the game uses**: the voice's sprites play on it too (`audioContext()`), since Safari handles one context far more reliably than two. A sound asked for while the context is paused waits for it to wake. Otherwise, the context is created on the first tap (with a moment of silence played inside it) and woken from any state but "running" on every tap, click or key, for iOS and for macOS Safari, which can leave it "interrupted". Before making the context it sets `navigator.audioSession.type = "playback"`: iOS mutes Web Audio on silent (the ring switch or Action button), and with the voice on the same context the whole game went quiet. If a tap finds the context still not running a second after an earlier tap tried to wake it (seen in the Home Screen app: the effects stopped partway and stayed silent), it's closed and a fresh one made inside that tap (`remade` in `status()`). A context can also come back from the background saying "running" but silent (seen in the Home Screen app: "Played" kept counting with nothing heard), so the first tap after the page was hidden remakes it, and so does a tap that finds its clock (`currentTime`) stopped. Settings → Game → **Test sound** always remakes it first (`sfx.restart`), as a fix by hand. Settings → Game → **Sound check** shows the context's state, effects played, restarts and the last error, with a Test sound button, for the Home Screen app, which has no address bar. Open the game with `?audio` to see the context's state, the audio session, errors and a Test sound button.
- **Music** (`music.js`, the background music section of `app.js`: `musicNow`, `stopMusic`, `duckMusic`): each stratum's Accents only ambience plays during a run, in the run's stratum (`wing().id`), at `DEFAULT_LEVEL`, on the one context (`sfx.audioContext()`, into its destination), with a new random seed each start.
- **Music is off for now** (2026-11-27): `MUSIC_ON` in `app.js` is false, so nothing plays and the Settings switch is hidden. Set it true to bring the Accents only music back.
  - **When**: only while a run is being played (`musicWanted`: `st.music`, `G.running`, not paused, not on the menu, the page not hidden, not mid-descent). So never on the start screen, the pause card (or Settings, the book, Items from it), the end card or after Exit. `musicNow()` starts or stops it to match, called from `start`, `end`, `pause`, `resume`, Exit, `menu`, `autoPause` and the setting, and once a second as a safety net (so it starts just after the descent lands). It fades in over 3 s and out over 1.2 s (0.5 s on a pause); Keep fighting starts it fresh.
  - **The context remade**: `sfx.onContext(fn)` tells it of every new context (the first tap, or a remake after the background or a stopped clock); music on the old one is dropped and starts again on the new one. Hiding the page stops it at once (`autoPause`), since iOS may close the context under it.
  - **Ducking**: `speech.js` `onTalk(fn)` reports when the voice starts and stops (`isTalking()`): every line, recorded, a quip (`playHero`) or the device voice, with a 350 ms gap before it counts as stopped, so a run of lines keeps it down. The music ducks (`duck(true)`, about −10 dB) while talking, and for a whole Hero Moment (`momentDuck` in `heroMoment`, released at the hit).
  - Its own switch, Settings → Game → **Music** (`st.music`, default on; `DEFAULT_SETTINGS` in `store.js`; it syncs like every setting). The sound effects switch doesn't touch it. Off stops it at once; on starts it in a run (from the pause screen's Settings, on Keep fighting). The Sound check has a Music line (off, on but not in a fight, or playing, ducked), and `?debug`'s `sumgeonState()` has `music`.
- `speech.js` `say(kind, text)` plays a recorded clip from `audio.json` when there is one, or falls back to the device voice.
  - Kinds: `p` phrase, `m` monster line, `n` number, `q` problem, `h` a hero's quip (Hero Moments).
  - Quips (`h`) are recorded in a second Kokoro voice, **`af_bella`** (`VOICE_FOR` and `voiceOf` in `build.mjs`, as Sound Box does for its quips), so a quip is never taken for an instruction. The voice is part of the clip's key. With the device voice, a quip is said a little higher (`PITCH` in `speech.js`).
  - Lines queue one after another; `say(kind, text, true)` clears the queue first. An optional fourth argument, `live`, is asked when the line's turn comes, and false skips it: lines about a problem pass `asked(G.cur)` in `app.js`, so they don't pile up behind a fast answer.
  - Names the voice should say differently from how they're written go in `SAY_AS` in `lines.js`: "Twodini" is said "Toodini" (too-DEE-nee, for the Houdini pun; Kokoro stresses "Twodini" up front), "Jr." is "Junior", "Mr." is "Mister", "Plusington" is "Plussington", "Chompette" is "Chomp-ette", "Nine-ja" is "Nineja" (NINE-juh, like the end of "ninja"; "Nine-jah" came out NINE-JAH), Chef Eight's "Bon appe-eight!" is "Bon appa-eight!" (APP-uh, not uh-PEH), "bows" (bending: the bosses' and Doublet's beaten lines) is said "bowse" (Kokoro said BOZE), the Palindrome achievement is said "Pal-in-drome!" (its `say` in `achievements.js`: Kokoro said PAY-lin-drome), "bandana" (the clothing piece) is said as "bandanna" (`PIECE_SAY` in `lines.js`: Kokoro said ban-DAH-na), "hexagon" and "pentagon" are "hexa-gon" and "penta-gon" in what's spoken (`sayShapes` in `shapes.js`: Kokoro said HEK-sag-un), and Sevenstein's "Six, seven" gets pauses (in his monster line and his quip). The quips' puns ("Bon appe-eight", "Zeroic", "Abraca-double", "Four-ward") read right as written. The spoken coin lines say "pennies" as "penny's" (`sayPennies` in `problems.js`): Kokoro reads "pennies" as "PEN-iz", close to "penne's", and "penny's" as "PEN-eez". Check a spelling with Kokoro's espeak phonemes before adding it (phonemizer in the Kokoro venv, run in `container`). These fixes usually come from the listen check.
  - Every line the game says lives in `js/lines.js` (`PHRASE`, monster lines, and `facts()` from `problems.js`: sums and differences within 20, the 2–12 tables and their division facts, each as the problem and as "… is …"). `app.js` only says lines from there; `scripts/lines.test.mjs` fails on any other `say()`.
  - `scripts/audio/build.mjs` (patterned on Sound Box's) records each line as one whole clip with Kokoro (`af_heart`, speed 0.95). Whole clips won a listen test against stitched numbers, which sounded choppy.
    - Clip names hash model, voice, encoding, method, speed, kind and text, so a clip never changes once made.
    - Each build reads the live `index.json` from the audio host and records only missing clips. **Only the sprites are deployed** (decided 2026-11-27; `DEPLOY_CLIPS` in `build.mjs` is false): the clips are kept in `_clips/` (out of git) to join the sprites from, and the clips already live are cut back out of the live sprites (each sprite's map gives every line's byte range, and from now its clip key, `keys`), so nothing is recorded twice and CI needs no cache. `index.json` still lists every clip key (each one's bytes are in a live sprite) and `s-` + each sprite key.
    - `audio.json` lists only lines whose sprite is live, so a line without one uses the device voice. It has no `base` unless the clips are deployed.
    - **The way back** if a device can't do ranged fetches: set `DEPLOY_CLIPS` to true and merge. The build sees the host's clips don't match it (a HEAD for one clip) and deploys again with `_audio/a/`, and `audio.json` gets `base`, so `speech.js` plays a line's clip when its sprite can't, then the device voice. The same check made the first build after the switch deploy without them.
    - With `GENERATE=false` (CI without the Cloudflare token) nothing is recorded.
    - Bigger problems (Hard mode, sums over 20) aren't recorded and use the device voice.
  - The audio host is the Cloudflare Pages project `sumgeon-audio`, served at the custom domain https://sumgeon.asset-data.stream/ (like Sound Box's). Use the custom domain, not `sumgeon-audio.pages.dev`: bare pages.dev ignores byte-range requests, and Safari's `<audio>` needs them. CI's `audio-deploy` job uploads the sprites; it needs the `CLOUDFLARE_API_TOKEN` secret.
  - To record locally on a Mac: `ASSET_BASE=https://sumgeon.asset-data.stream/ KOKORO=container KOKORO_DIR=<folder for the model and venv> node scripts/audio/build.mjs`. ## Core rules
- Damage = the correct answer. Three correct in a row turns on crits (double damage) until a miss. A hinted answer still hits but doesn't build the streak.
- Problems come from the learning engine (`learn.js`, DESIGN.md §5), not at random:
  - Each player has a record per fact (`facts`): box 0–4, times seen and right, average answer time, last seen.
  - A right, unhinted answer moves a fact up a box (two when fast, from box 1). A miss sends it to box 0. A hinted answer changes nothing.
  - **Fluent** means right, unhinted and under `fluentTime(band.fluentMs, answer)`: 4 s in K, 1st and 3rd (6 s in 2nd grade's two-digit band; counting the reading and the taps), plus 1 s for each extra digit to tap. At 3 s, about half a fluent adult's answers counted as slow.
- **Skipping ahead** (`tiers`, `probeKey`, `skipTo` in `learn.js`): each band's facts, easiest first, are cut into tiers of about 20 that stay inside a level. After two fluent answers in a row, each problem is a probe: a fact not yet learned from the tier above the first one not yet learned, never past the player's chapter (`reachOf`; a band's levels are in its path's order, so tiers climb the path). **5 fluent out of the last 6 probes** (`SKIP_PROBES`, `SKIP_WINDOW`) count everything below the probe's tier as known ("You already know these. Skipping ahead!"), so one mis-tap doesn't undo it; a skip in the stratum's own band also places its review steps (`placeReviews`). Two slips in the window pause probing for 3 problems. Skipped facts come back as reviews.
  - **Leaps:** probes start one tier above the frontier, and each skip in a row doubles how far up they come from (1, 2, 4 tiers, `MAX_LEAP`); a slipped window drops it back to 1. With one tier per skip, a fluent adult on an iPhone took 6+ runs, since a fluent run is only about 8 K problems (crits end floors in a hit or two).
  - The tally (`flowOf` in `app.js`) is per player and band, so slow coin probes on Trollar's floor don't cut short a run of fluent sums, and it carries from run to run while the game is open.
  - `node scripts/balance-sim.mjs [stratum]` plays each stratum's path (the window, chapters opened by the mega boss every 5 depths, each floor's monster from the open steps, the review steps, the boss powering up, skipping ahead), a simulated player winning every run and going deeper each time, and prints runs to 60% of the priority steps for a fluent, a slower, a part-fluent player and a learner, when each chapter's first step joins, and the most new steps open when one joins (never more than three). Medians with the paths (2026-11-26, up to 40 runs): Cellar 6 / 8 / 17 / 27; Hall 7 / 13 / 35 / never; Mines 6 / 6 / 7 / 40; Tower 6 / 6 / 28 / never. A fluent player opens the next stratum just after the first mega boss. Medians before the paths: Cellar 3 / 8 / 18 / 25 (the dot flash, Pipsqueak's strand, moved it by a run either way); Hall 4 / 9 / never in 30 / never in 30; Mines 4 / 5 / 5 / never in 30 (it was 28 before the three-digit work); Tower 4 / 5 / 30 / never in 30 (Polly-Gon's shape floors, a strand in every stratum and a depth-1 floor in the Mines, cost about a run here and there, being strand floors that don't count toward the 60%; the three-digit work's 88 facts and Chompers and Triceraplus visiting the Mines push the Mines' learner past 30 runs; Margot-Rythm visiting the Tower costs its part-fluent player about 3; the new monsters cost the part-fluent player a few runs in the Hall: two of its five monsters ask narrow sets; batch 1's strand floors, time and patterns, cost a run or two more, since they don't count toward the stratum's 60%; batch 2's band facts cost about a run each for a fluent player, and the Hall's true or false, asked by the Equal Twins and Judo Judy only, about 4 for the part-fluent one; the Mines' place value about 11 for a learner; comparing fractions, a Tower level asked by Chompers visiting and by Halfling, changed no median). A learner never skips.
- **Placement:** a fact seen for the first time and answered right, fast (under the band's `fluentMs`) and unhinted is already known and goes straight to box 3 (learned), so a fluent player isn't held back.
  - Each problem is about 60% learning facts (box 0–2, box 0 favored), 25% review facts that are due (box 3 after 10 minutes, box 4 after a day), and 15% new facts from the first open level that has any (so a step's levels, and the window's steps in one band, arrive in the path's order). The monster's operation is preferred 70% of the time, but when none of its operation's facts are new, the new ones come from everything open, so a new level of another kind (fractions under Timesaur) still arrives. No fact repeats within the last 12 problems (`RECENT`, `notRecent` in `learn.js`), so a fight doesn't ask the same one twice; a monster with only a few to ask (Doublet early on) keeps out the last 3, then none. A missed fact still comes back on purpose.
  - **What a monster asks at all** (`asks` in `traits.js`, `opts.asks` in `choose`, `probeKey`, `spellKey`, `monsterHP`): Chompers only compares (`○`, or `more` in the Cellar; in the Tower, fractions), the Equal Twins only balance and say whether an equation is true (`=`, `✓`, `✎`), Judo Judy (the Hall's boss) the Hall's whole mix, Quizard everything but comparing, Pipsqueak only the dot flash (`⁙`) and dice sums (both numbers 1–6, `isDice`), Doublet only doubles and taking half away (8 + 8, 16 − 8, 7 + □ = 14, 40 + 40; `isDouble`), Triceraplus only adding several numbers (`Σ`), Halfling only fractions (`/`, the number line `↔`, and comparing fractions `○`), Margot-Rythm only + and − (not place value), Tick-Tockus only the time (`⌚`), Slimelipsis only patterns and odd and even (`…`, `◐`), Polly-Gon only shapes (`◇`), and every other monster never compares or balances, says true or false, tells time, counts patterns or asks shapes. `asks(m)` is a test on a fact's operation and key (`asks(m)(op, key)`), so a trait can pick facts by their numbers. With none of its kind open yet, it asks its kind from the lowest level that has it.
  - A missed fact comes back 2–4 problems later.
  - **The captain's digit:** in a player's first fight (nothing beaten yet, so no Hero Moments) about 85% of problems avoid it (`CAPTAIN_HOLD`, `avoidDigitShare`; about 18% → 2% of answers), then about a third of problems prefer answers with it (`CAPTAIN_BIAS`, 0.35, `digit`/`digitShare` in `choose`; about 18% → 47%) until that captain's first Hero Moment has happened (`captainLean`, `MS.captains`), at any depth. Then problems are neutral; a new captain gets the lean again. It only narrows which facts are open; the learning, review and new shares are unchanged.
  - **Variety:** a problem is never the same kind (operation) with the same answer as either of the last two when there's another choice (`avoidAns` in `choose` and `probeKey`, as "op ans"). The same answer from a different kind (3 + 7 after 17 − 7) is fine. The teen subtraction facts all equal 10, and with Minustaur preferring − they came up in a row.
- **Bands** (`BANDS` in `learn.js`): one per grade, each one stratum's facts, with its levels in the school's teaching order (DESIGN.md §4.1):
  - **`kinder`** (the Counting Cellar, 7 hearts): within 5, with zero (4 + 0, 4 − 0, 4 − 4) → within 10 → make 10 (7 + □ = 10) and number bonds of 5–9 (4 + □ = 6) → 10 and some more (10 + 4, 14 − 4, 10 + □ = 14).
  - **`first`** (the Balance Hall, 7 hearts), cut along its path: within 20 not crossing 10 (13 + 4, 17 − 5; within 10 and 10 and some more are the Cellar's, and a teen take away a teen is left out) → crossing 10 → doubles and near doubles (8 + 8, 7 + 8, 16 − 8, 15 − 7; Doublet) → the equal sign (true or false and fix it, to 10 and 20; the other side and balance both sides; 24 □ facts like 8 + □ = 13) → compare with < = > (to 10, sums, to 100; Chompers) → add and subtract tens (40 + 30, 70 − 30, 10 more, 10 less, 34 + 20) → add two-digit numbers, then with regrouping (moved from the Mines, the same keys; the Mines keep them too).
  - **`second`** (the Crystal Mines, 5 hearts, `fluentMs` 6 s): two-digit + and − without regrouping (add ones, add tens and ones, subtract), mixed → with regrouping → hundreds, tens and ones (blocks, expanded form) → tens in a number (how many tens in 120, odd splits) → 10 and 100 more or less within 1000 (345 + 10, 405 − 10, 345 + 100) → add within 1000 → add with regrouping → subtract within 1000 → subtract with regrouping (2.NBT.B.7): place value (batch 2) comes before the three-digit work, as the school teaches it.
  - **`third`** (the Tables Tower, 5 hearts): all of × before ÷ (confirmed by the class): × 0, 1, 2, 5, 10 → × 3, 4, 6 → × 7, 8, 9 → ÷ 1, 2, 5, 10 → ÷ 3, 4, 6 → ÷ 7, 8, 9 → × tens (4 × 30) → rounding → fractions on a number line (batch 2) → equal fractions (and the 0 to 2 line) → compare fractions → area and perimeter → × and ÷ 11 and 12. × and ÷ only: no + or −.
  - **Strands** (`strand: true`): small bands a stratum gives one monster, asked on its floor, opened by the path like any level: `coinsK` (find the coin, each coin; Trollar in the Cellar), `coinsH` (each coin's worth, the same keys; Trollar in the Hall), `coins` (counting: pennies, nickels, dimes, quarters, then batch 2's dollar bills and bills and coins; Trollar in the Mines), `more` (which is more; Chompers in the Cellar), `flashK` (the dot flash, then dice sums; Pipsqueak in the Cellar), `three` (three numbers; Triceraplus in the Hall), `sumsM` (up to four two-digit numbers; Triceraplus in the Mines), `cmpM` (comparing three-digit numbers; Chompers in the Mines), `addT` (adding and subtracting within 1000, 3.NBT.A.2; Margot-Rythm in the Tower, the Mines' three-digit facts with the same keys), `arrays` (Squaresquatch in the Mines), and batch 1's time (Tick-Tockus: `timeH` in the Hall, `timeM` in the Mines, `timeT` in the Tower) and patterns (Slimelipsis: `patK` in the Cellar, `patH` in the Hall, `patM` in the Mines), and shapes (Polly-Gon: `shapesK`, `shapesH`, `shapesM`, `shapesT`, one in each stratum). A stratum's `strands` map in `WINGS` decides (`bandOf` in `wings.js`); a monster has no strand of its own.
  - **Paths** (`PATHS` in `wings.js`, `openSteps` in `learn.js`, DESIGN.md §4.3): each stratum has one path of steps in its grade's teaching order. A step is a few of these levels (`parts: [[band, level]]`, named in `PATHS`, so keys and records don't change), its monsters, its chapter, and flags: `priority` (the guide's priority standards; only these count toward opening the next stratum), `ongoing` (open from the start and kept open: the dot flash and which is more, and counting, in K; counting to 120 and back from 20 in 1st), `review` (an earlier grade's facts: never new; learned ones come back as due reviews to the monsters asking the stratum's band, `reviewFacts`; for a player who never learned them they're placed by skipping ahead, `placeReviews`). Every level is in exactly one step, review steps aside (`scripts/paths.test.mjs`).
    - **Review steps** ask only facts already seen once at least `REVIEW_MIN` (8, `asked` in `learn.js`) of them have been; with fewer, they practise the rest of their level too, so one seen fact isn't asked over and over (a 3rd grader got 266 + 302 from Margot-Rythm every time).
    - **The window**: about three new steps are open at once (`WINDOW`); a step stops being new at 40% learned (`JOIN_AT`, box 3+), and then the next joins, so there are never more than three new ones. A step already learned (placed, skipped, from another stratum) joins and is done at once. The most that ever joined is saved (`wings[id].steps`) so a miss never closes one. `choose`, `spellKey`, `monsterHP` and the shapes' counting take the band's open levels (`openLevels`).
    - **The Cellar's coins come last** (chapter 2, after Shapes; moved 2026-11-27): kindergarten learns the coins near the end of the year, and they had come right after Within 10. Make 10 moved up into chapter 1 in their place. Trollar arrives with them, and money in chests and the shop waits for a coin answered right in K (`moneyOK`).
    - **Chapters**: steps come 3–4 a chapter (Cellar 2, Hall 3, Mines 3, Tower 3); a step past the player's chapter never opens, and probes stop at its end. The chapter is 1 + the mega bosses beaten there (`chapterOf`, saved as `wings[id].megas`, counted by the mega depths beaten so a replay doesn't count twice).
    - Every fact is recorded (`lines.test.mjs` checks the asked and answered line of every fact in every band), so every problem has the recorded voice.
  - **Fact keys** are unchanged for every fact that existed, so what's been learned carries over. Damage: the dollars, or for bills and coins the cents. Never a decimal. Hint: counting on from the biggest bill, then the coins, partway (`countedOf`), "…" and "?".
  - **Stacked sums** (`stackOf`, `STACK_SHARE` in `twodigit.js`; `stackHTML` in `app.js`): a two- or three-digit + or − (past 20, not a □, Judo Judy's throw or dice) is shown in columns a quarter of the time (`STACK_SHARE`), half the time for three-digit numbers and for adding several two-digit numbers (`STACK_SHARE3`, `stackShare`), and always on Margot-Rythm's floor: ones under ones, a line, and the answer's □ under it, right-aligned (`.stacked`). The same fact and record; the hint is the same place-value strategy (tens and ones, then together), never carrying. `?stacked` stacks every one. The purse's `.stack` styles are scoped to `.stacks` (they used to restyle `.game.stack` and broke the stacked layout).
    - The answer under the line is **typed right to left**, ones first, as it's worked on paper (`press`, `stackCells`, `onesFirst` in `app.js`): one cell per column, a blinking gold cursor in the next column to fill (still under reduced motion, just not blinking), and delete takes back the last digit typed. **Only stacked problems** are ones first, on every floor, Margot-Rythm's too (2026-11-27: answers written across are typed left to right there as everywhere). The first 3 say "Start with the ones!" (`PHRASE.onesFirst`, `once("onesFirst", 3)`). Typed the other way round (fast, tens first, so 42 comes out 24), the digits **visibly swap places** first (`flipCells`: each arcs to its mirror column, glowing gold, about 0.9 s; a glow only with reduced motion), with "Ones first! Let's flip it." and "Start with the ones!", then it's answered as a hinted answer: it hits, but builds no streak and isn't fast.
    - **Columns line up by cells, not the font:** each digit of the numbers above the line sits in a fixed-width cell (`.scols`/`.scell`; the answer's cells are the same width), and the answer's dashed box is pulled out by its border and padding, so ones sit under ones at any length. Bungee has no tabular figures (its only OpenType features are `locl` and `vert`; its digits run 601 to 727 units wide), so `font-variant-numeric: tabular-nums` does nothing for it.
- **Shapes** (`js/shapes.js`, Polly-Gon, from `review/proto/`; K.GM.A, 1.GM.A, 2.GM.A, 3.G.A): 64 fixed facts in four strands, one per stratum (`SHAPE_STRANDS`, levels by their keys; strands share keys, so a triangle's sides learned in the Cellar count in the Hall):
  - `shapesK` (Cellar): draw and count circles, squares, triangles, rectangles (10) → hexagons, and the sides and corners of any shape of 3 to 6 sides (11).
  - `shapesH` (Hall): sides and corners, whatever the shape (17) → halves and fourths of circles and rectangles (8).
  - `shapesM` (Mines, fluent at 7 s): sides, corners (2nd grade's angles) and faces, with pentagons, a cube (6) and a square pyramid (5) (17) → equal shares in 2, 3 or 4 (11; a priority standard) → rows and columns of squares, counted (12).
  - `shapesT` (Tower, `strict`): quadrilaterals: draw a rhombus, a square, a rectangle, any quadrilateral, and count sides and corners (12) → unit fractions: a circle or rectangle in 2 to 8 equal parts, one shaded, "Each part = 1/□" (11).
  - **Keys**: `◇draw:tri` (draw it; also circle, sq, rect, rhom, pent, hex, quad), `◇sides:hex` and `◇corners:tri` (a named shape, drawn turned one of the ways it's met), `◇sides:5` (a shape of 5 sides drawn uneven and turned any way, so it's counting, not knowing a name), `◇faces:cube`, `◇faces:pyramid`, `◇parts:circle4` and `◇parts:rect2a` (a rectangle cut across, down, corner to corner (x) or in a grid of 2 rows (g)), `◇squares:3,4` (3 rows of 4), `◇unit:rect6g`.
  - **Draw it** (touch screens only, like spells, `canSpell`): "Draw a triangle!" on the spell pad (`padUI("draw")`, Clear and Cast!), read by `readShape` ($P with shape templates, the corners counted along the strokes, and the aspect for a square or a rectangle) and judged knowing the shape (`judgeShape`, `castShape` in `app.js`). Right (a good or a rough match): a hit, and the clean shape glows over the drawing, theirs dimmed (`cleanFor`). Read clearly as another shape: a miss, "That looks like a square! Here's a triangle.", the right shape glowing over it and the Oops card's worked hint. A drawing that ran off the pad (`offEdge`, as for spells: `judgeShape(r, asked, strict, edge)`) is never that miss: off the edge and not right is a retry, "Stay inside the box! Try again." (`PHRASE.drawEdge`); right off the edge still counts. Unclear: "Try again!", no cost; after two, a counting problem about it takes its place ("Let's count instead!", `drawToCount`), as a spell falls back to the pad. Unlike a spell, a drawing records the fact like any answer: it's the math here. On a mouse or keyboard, drawings are never asked (`drawable` wraps the monster's `asks`); drawing is at most 40% of any level, so counting alone still opens the next.
  - **A square for "rectangle"** counts in every grade (`accepts`): it is one (four square corners), 3rd grade says so (3.G.A.1), and the K and 1st grade guides don't set them apart, so a kindergartner isn't marked wrong for it. A long rectangle is never a square. "Quadrilateral" takes any four-sided shape. 3rd grade (`strict`) only tells a square from a rectangle more closely. A wide or tall oval counts as a circle (kids' circles on the wide pad), and a round shape is allowed a couple of corners (`CIRCLE_CORNERS`).
  - **Damage**: a drawing hits for its strand's typical answer, the mean of its counting answers (`drawHit` in `learn.js`: 4 in the Cellar and the Hall, 6 in the Mines, 5 in the Tower), so it's neither a weak nor a big hit and fights last the same; a shape's own sides would make a circle a wasted turn and a hexagon worth twice a triangle. A count hits for the count.
  - **Count it**: the shape over its line ("Sides = □", "Faces = □", "Equal parts = □", "Squares = □", "Each part = 1/□" stacked), typed. Hints are drawn on the shape (only the words open): sides, corners and parts are numbered about halfway, "1, 2, … How many?" (`partsCounted`), the rest dimmed; a cube's 3 faces you see and 3 behind; squares by rows, partway (`rowsCounted`); a unit fraction's parts counted halfway, "Each part is 1/?". A drawing's hint is its corners as dots to join, the first sides drawn ("A triangle has 3 corners. Join the dots!"); worked, the whole shape, each side numbered.
  - Spoken: "Draw a triangle!", "How many sides does this hexagon have?", "How many corners?", "How many faces does this cube have?", "How many equal parts?", "How many squares in all?", "The whole is cut into equal parts. Each part is one what?"; answered "A triangle has three sides and three corners.", "It has five sides.", "Four equal parts: fourths.", "Three rows of four make twelve squares.", "Each part is one fourth." Read aloud as they appear; the listen check's Shapes group.

    - **Variants** (`VARIANTS`): $P scales evenly, so a slanted or stretched digit is a different cloud. Every shape is also a template slanted about 14° each way, narrower and wider (375 templates in all).
    - **Mirrors**: every shape's mirror is a template that means reversed (not for 0, 8 or a plain 1; the mirror of a one-stroke 8 is the same digit begun at the top left).
    - **Speed**: a quick pass (one greedy match, one way) keeps the closest 24 templates and the closest 3 of each digit for the full $P match, about 10 ms a read in Node.
    - A read is **clear** when its fit is at least `CLEAR.fit` and it's ahead of the next digit by `CLEAR.margin` (15%), or `CLEAR.reversed` (20%) when it reads as backwards: every mirror is a template too, so a backwards 9 sits close to a backwards 4 or 7, and most drawings face the right way.
    - It counts as **reversed** only when the mirror is clearly the better match (`REVERSED_MARGIN`), so a wobbly 1 gets the benefit of the doubt.
  - **Outcomes** (`judge(read, answer)` in `sigil.js`: the game knows the answer, so a drawing only has to look like it):
    - **Wrong:** only a clear read of another digit. It's checked first, so a clear read is never overruled.
    - **Backwards:** a clear read of the answer facing the wrong way: half damage, the digit shown the right way round with an arrow, and "Your 3 is facing backwards. It faces this way."
    - **A good match** (`hit`): the answer is the best digit, facing the right way, fit ≥ `ACCEPT.good` (0.5) and clear or close to it (margin ≥ `ACCEPT.near`, 5%). It hits, and the drawing is saved as one of the player's own templates (the last 3 per digit), unless the built-in templates alone read it clearly as another digit.
    - **A poor match** (`show`): the answer is the best digit, or its own best fit (facing the right way) is within `ACCEPT.gap` (0.05) of the best digit's, at fit ≥ `ACCEPT.floor` (0.25), but it isn't a good match. The math was right, so it hits for full damage, but it isn't learned: the school-style digit (`handwriting.js`) is **written stroke by stroke** over the dimmed drawing (`showHowToWrite` in `app.js`: each stroke in order at an even speed with a gold pen dot at its tip, a breath between strokes, held a moment; drawn whole at once with reduced motion), and the hit waits for it, the message says "Here's how to write it", and the voice says "Here's how to write a four." (`howToWriteLine`, recorded for 0–9). So a kid's odd shape gets taught, not kept.
    - **Anything else:** "Incantation failed!", no heart lost, try again. After two, the number pad comes back.
    - **Off the edge** (`edge`, above): a drawing that ran off the pad is never wrong or backwards, only a retry, since part of it may be missing.
    - The numbers come from the fixtures: every real drawing fits its digit at 0.6 or better except drawer-2's squared-U 4 (0.27), which lands in "poor". A gap of 0.05 is about a third of the clear margin; it accepts some drawings for an answer they aren't (they hit, and show the right digit), never a clear read.
  - **The throw:** a good spell's drawing itself flies at the monster (`drawingShot`, `G.spellShot`, `fly` in `app.js`): the strokes, cropped and glowing, lift off the pad (which clears) and arc into the monster in place of the chalk digit. A backwards or poorly matched spell throws the plain digit, since its drawing is the one being corrected, and a Hero Moment plays instead of the throw.
  - **Kept out of learning:** a spell changes no fact record, timing, placement, skipping or the "all fast" star.
  - **Saved** per player as `spells`: `{ templates, reversed: { digit: count }, cast }`.
  - **The spell check** (`review/spell/`, at `/sumgeon/review/spell/`): a grown-up page, built like the listen check, in two modes.
    - **Try it:** draw any digit and see the read, its fit and margin, and whether it's reversed, with or without a player's learned handwriting. **Expecting** picks an answer (or none) and shows what the game would do: hit (and learn it), hit and show how to write it, backwards, wrong, or try again. ## Linking and sync (DESIGN.md §15, patterned on sound-box-crosswords)
- **What it is:** a player can be linked to other devices (Settings → Players → "Play on another device too" shows a QR code and a link; "Get a player from another device" scans it with the camera or takes a pasted link, then asks "Who is this?": the same player as one here (Keep both adds the progress up; Replace takes theirs), or someone new). A page opened with `#link=` drops it from the address and opens Receive. The status ("Synced", "will sync later") is only in Settings → Players, never where a kid plays. Removing a player (✎ → Remove) only ever removes it from this device; the synced copy and other devices keep it.
- **Privacy** (`js/seal.js`): the 43-character link key is in the link only. HKDF derives the lookup id the server sees, an AES-256-GCM key and a request token, so the server keeps a sealed copy it can't read, with no names or accounts. Anyone with the code can change that player's progress, so it's shown only for your own devices.
- **Merging** (`js/merge.js`, `scripts/merge.test.mjs`): order-independent and idempotent. Tallies (times seen and right) are kept per device; earned things only grow (strata, depths, stars, megas, Legend, bestiary, heroes, owned clothes and plushies, quips heard); a fact's box and average time come from the device that practised it last; settings merge by an edit counter. The **wallet and each item** are per-device ledgers of earned and spent, so syncing never makes or loses a coin or an item. The run in progress never syncs. `RECORD_VERSION` keeps an older app from overwriting a newer record.
- **Deliberately lazy** (`js/sync.js`, `syncAll` and `syncSoon` in `app.js`): it shares the Cloudflare account's free-plan quotas with Sound Box's `sound-box-sync`, and a late sync costs nothing. It syncs at launch, on returning to the app after 10 minutes or more away (`SYNC_AGAIN_MS`), and at the end of a run; Send and Receive sync at once. Each sync is one fetch, merge and save, retried once on a 409. Busy or over a limit, it says "will sync later" and waits until midnight. Unlinked players never touch the network. The service worker leaves sync requests to the network.
- **The service** (`sync/`, the Worker `sumgeon-sync` at `sumgeon-sync.asset-data.stream`, `workers_dev: false`; `scripts/sync.test.mjs`): one SQLite Durable Object per linked player holding its latest sealed record, the token on every request (the first save sets the owner), 409 on an out-of-date save, records deleted 90 days after their last save (`KEEP_DAYS`). Requests only from https://tools.tuley.name and localhost. Caps, set low because the account's quota is shared: a record up to 32 KB (`MAX_BYTES`; the biggest realistic player, every fact for three years on two devices, seals to about 24 KB: `node scripts/sync-size.mjs`), 3 new players a day per network and 50 a day in all (`NEW_PER_NETWORK`, `NEW_PER_DAY`), 10 MB stored in all (`SPACE_BYTES`), and 60 requests a minute per network (`NET_LIMIT`, rate-limit namespace 1002, apart from Sound Box's 1001).
- **Deploying:** CI's `sync-deploy` job (main only, after the check) runs `wrangler deploy` in `sync/`. Sumgeon's Cloudflare token is a user token with Pages: Edit and Workers: Admin (Admin creates a Worker; Editor only updates one), and no zone permission. So `wrangler.jsonc` has no routes: the custom domain `sumgeon-sync.asset-data.stream` was attached once in the dashboard (Workers & Pages → sumgeon-sync → Settings → Domains & Routes), and deploys leave it alone. Without the secrets the job skips.
- **Trying it locally:** `npx wrangler dev` in `sync/` (port 8787), then open the dev server with `?sync=http://localhost:8787` (remembered on that device; localhost only).
- **Libraries** (`vendor/`, with their license texts, credited in the README and About): qrcode 1.5.4 and dijkstrajs 1.0.3 (MIT) draw the code; jsQR 1.4.0 (Apache-2.0) reads it.

## Opening, and when it doesn't
- `index.html` keeps the page on the launch color (`html.boot`) until `app.js` has drawn the start screen. ## Offline
The game plays offline, voice and all, once it's been opened online and has had time to save (DESIGN.md M8). `sw.js` (a classic-script service worker at the site root, scope `./`, so `/sumgeon/`), registered from `app.js`, with its rules in `route()`, tested in Node by `scripts/offline.test.mjs`:
- **The shell, per deployed version:** `stamp.mjs` fills in `VERSION` (the short sha) and `SHELL` (`shellFiles` in `stamping.mjs`: `./`, every `STAMPED` file, every `js/*.js` module, the manifest's icons and the fonts, all `?v=<sha>`; about 1.1 MB). It's precached whole on install (`cache: "reload"`, so the HTTP cache can't slip in an old `index.html`), in `sumgeon-shell-<sha>`. A new deploy is a new `sw.js`, so the browser installs it; `skipWaiting` and `clients.claim`, then the old versions' shells are deleted. That's safe because every file is stamped: an open page keeps its own files, and `checkUpdate` reloads at the start screen as before.
  - **Cache rules:** the page (`./`, `index.html`, any `?v=`) is network-first, falling back to this version's cached shell offline; stamped `?v=` files are cache-first; `version.json` is never cached (the update check always asks the network); `audio.json` is network-first with the last copy kept (`sumgeon-data`, also fetched on install); the grown-up pages are online only. A ranged request for a sprite (a line on its own, from `speech.js`) is answered from the saved sprite when there is one, cut to the range (a 206, `rangeOf` in `sw.js`), and otherwise goes to the network as it is. Other ranged requests, and single clips (`_audio/a/`, the audio host's `/a/`, which only an older page asks for now), are left to the browser.
  - Cache names all start `sumgeon-`: tools.tuley.name hosts other apps, whose caches are never touched.
- **The voice** (`sumgeon-voice`, cache-first by address, since a sprite's address is its content's hash): after the first tap (1.5 s later), `speech.js` (`saveVoice`, `saveSome`) saves every sprite in audio.json, two at a time, in the order `app.js` gives (`voicePlan`, `saveOrder` in `offline.js`): `ALWAYS`; this stratum's `runSprites`, monsters then lowest level first (`byLevel`); the other open strata's, in WINGS order; then every other sprite, so a new stratum or depth works offline too. It never starts one while a sprite the game needs now (`needSprites`) is loading. Through the worker, fetching a sprite is what saves it (it answers only once the sprite is kept); before the worker takes over, the page keeps it itself. Sprites an update dropped from audio.json are deleted. A failed fetch (offline) stops it until the next plan (the start screen, a run) or the `online` event. The whole voice is 146 sprites, about 97 MB.
  - The audio host answers with `Access-Control-Allow-Origin: https://tools.tuley.name` (`_headers` from `build.mjs`), so the sprites are readable (CORS) responses: an opaque one would count hugely against Safari's quota, and the worker never keeps one.
  - It asks once, quietly, for persistent storage (`navigator.storage.persist()`).
- **Settings → Game → Sound check** says how far it's got (`offlineStatus` in `speech.js`, `offlineLine` in `offline.js`): "Offline: ready (all 146 voice files, 97 MB)", "Offline: saving the voice, 12 of 146 files (8 MB of 97 MB)…", "…the rest when back online", or "not available on this device", and the storage used (`navigator.storage.estimate()`).
- **Dev mode:** the dev server serves `sw.js` as it is (`VERSION` "dev"), and the worker is network-first for everything, keeping one copy of each file under its address without the stamp (`sumgeon-dev`) only as the fallback when the network is gone, so an edit is never stale. The page posts what it loaded before the worker took over (`warm`), so the first visit works offline too. Sprites are cache-first there too.
- **The fonts** (`fonts/`, latin only, as Google Fonts serves them: Bungee, and Nunito as one variable file for every weight) load through `@font-face` in `styles.css`; `stamp.mjs` stamps their `url()`s (`stampCss`). The grown-up pages and `design/social/make.mjs` still load Google Fonts. Their licenses are `fonts/*-OFL.txt`.
- `npm run check` syntax-checks `sw.js`, checks `stamp.mjs` can stamp it and the fonts, and `offline.test.mjs` checks the shell is exactly what the stamped page loads, the cache rules and the save order.
- `node scripts/offline-browser.mjs [dev|site] [port]` (Playwright via `NODE_PATH`, muted, speech stubbed; needs the local recording in `_audio/` and `audio.json`) loads the game on the dev server or a stamped `_site/`, taps, waits for the whole voice, goes offline, reloads, and checks the start screen, the fonts, a fight and lines decoded from saved sprites.
- Single clips aren't deployed (DESIGN.md M5): a device that hasn't saved a line's sprite fetches just that line with a `Range` request (see Sound and voice).

## Publishing
- Public repo `jbtule/sumgeon`. Pushing to `main` deploys to GitHub Pages at https://tools.tuley.name/sumgeon/ through `.github/workflows/ci.yml`. `scripts/stamp.mjs` builds `_site/` (Sound Box's pattern): it copies the files in `SITE`, adds `?v=<short sha>` to each local file the page loads (`STAMPED`), and fills in the footer's GitHub badge with the short sha so you can see what's deployed (locally it reads "dev"). Add new site files to `SITE`, and anything the page loads to `STAMPED` (which also puts it in the service worker's precached shell, see Offline).
- **Icon**: Plusquito on the Cellar's bricks. `design/icon/` holds the source (see its README): `make.mjs` draws the layers and `favicon.svg`, and `site.py` renders `apple-touch-icon.png` and the manifest's `icon-192.png`/`icon-512.png` from the Icon Composer document. `manifest.webmanifest` (standalone, the Cellar's brown) and the icons are stamped like the page's other files.
- **Update checking** (`checkUpdate` in `app.js`): `stamp.mjs` writes `version.json` (`{ sha }`). The game asks for it, uncached, when it wakes up (visibilitychange, focus, pageshow, so also the Home Screen app coming back) and every 15 minutes. If a different version is deployed, it reloads at the next safe moment: the start screen, never mid-run (Settings and Monsters & Heroes wait too). The reload adds `?v=<sha>` to the address so the browser can't reuse its cached old page, and it tries once per version (`sumgeon:update` in sessionStorage), so a stale cache can't loop. The reload fades the page to the launch color first (`html.reloading`, 0.15 s), where the new page fades in from (above), so it isn't a hard blink. Locally the badge reads "dev" and nothing is checked.
- Workflows must pass `zizmor .`: actions pinned to a SHA, minimal `permissions`, and `persist-credentials: false`. CI runs zizmor too.
