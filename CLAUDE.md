# Sumgeon

A math-practice dungeon crawler. The player fights anthropomorphic monsters built from numbers and math symbols, and the answer to each problem is the damage dealt.

## Current state
- Plain static files, no build step: `index.html` (markup), `styles.css`, and browser ES modules in `js/`:
  - `app.js`: everything on screen (game loop, menu and players, attack animations)
  - `problems.js`: facts and spoken text (`facts`, `spoken`, `spokenProblem`, `spokenFact`)
  - `learn.js`: the learning engine: bands and levels, fact records, choosing problems, monster HP
  - `hints.js`: the classroom models for hints (`hintFor`)
  - `lines.js`: every line the game says
  - `monsters.js`: monster data and SVG art
  - `store.js`: saved data (players, storage upgrade)
  - `sfx.js`: Web Audio sound effects
  - `sigil.js`: reading a drawn digit for spells (a $P point-cloud recognizer and its templates)
  - `speech.js`: `say(kind, text)`
  - `moments.js`: Hero Moments' rules (when one happens, whose, which quip; the quip decks; the rarity simulator)
  - `slowmo.js`: Hero Moments' show (the slow-motion close-up), shared by the game and `moments/`
  - `handwriting.js`: the digits 0–9 in plain school-style handwriting, as strokes (`HANDWRITING`, `handwritingPath`), drawn by the game and the spell check
  - `drawings.js` and `zip.js`: the spell check's recorded drawings and the zip they're shared in
  The modules other than `app.js`, `sfx.js` and `speech.js` have no DOM and run in Node.
- Modules need http, so run it with `npm run dev` (`scripts/dev-server.mjs`, port 8791, or `node scripts/dev-server.mjs <port>`), then open http://localhost:8791. Opening `index.html` as a file won't work.
  - The dev server stamps every page on the fly the way the deploy does (`scripts/stamping.mjs`, shared with `stamp.mjs`): each module gets `?v=dev<…>`, which changes whenever a file changes. It also sends no-cache headers and byte ranges (Safari's `<audio>` needs them). A plain static server lets Safari keep stale modules on a phone.

## Players and saving (patterned on sound-box-crosswords)
- `sumgeon:` holds the device's own data: `profiles` ([{ id, name }]), `profile` (who's playing), `storage` (version) and `device`.
- `sumgeon:@<id>:` holds one player's data. Every key saved there must be in `OWN_KEYS` in `store.js`, which throws on any other key.
- **Dungeon version** (`DUNGEON_VERSION` in `app.js`, saved per player as `dungeon`), while we're before release: bump it when a balance change means saved runs should start over (how fast heroes are freed, how strata open). On the next load each player's dungeon progress resets (`wings`, `bestiary`, `best`, and heroes back to just their own captain, via `resetTeam`), keeping their hero, chalk color and settings. What's been learned (`facts`) is kept too, unless the version is in `LEARNING_RESETS` (version 3: placement and skipping ahead changed how learning counts). Add a line to its list saying why. Stop bumping it once real players are using the game.
- Storage version 2 moved the prototype's single `sumgeon` key into the `default` player, resumably.
- Names belong to the device. Remove only appears on a device with two or more players, never for the one playing, confirms with a second tap, and only affects this device.
- `told` (per player): how many times the voice has explained each thing (`{ tag: count }`, `once` in `app.js`), so explanations aren't repeated every time.
- Settings (`band`, `sfx`, `voice`) are per player and save as they change in the menu. `ops` and `diff` are the prototype's, kept only so a player who practiced × or ÷ starts in Apprentice.

## Sound and voice
- `sfx.js` synthesizes every effect with Web Audio, on **the one Web Audio context the game uses**: the voice's sprites play on it too (`audioContext()`), since Safari handles one context far more reliably than two. A sound asked for while the context is paused waits for it to wake. Otherwise, the context is created on the first tap (with a moment of silence played inside it) and woken from any state but "running" on every tap, click or key, for iOS and for macOS Safari, which can leave it "interrupted". Before making the context it sets `navigator.audioSession.type = "playback"`: iOS mutes Web Audio on silent (the ring switch or Action button), and with the voice on the same context the whole game went quiet. Open the game with `?audio` to see the context's state, the audio session, errors and a Test sound button.
- `speech.js` `say(kind, text)` plays a recorded clip from `audio.json` when there is one, or falls back to the device voice.
  - Kinds: `p` phrase, `m` monster line, `n` number, `q` problem, `h` a hero's quip (Hero Moments).
  - Quips (`h`) are recorded in a second Kokoro voice, **`af_bella`** (`VOICE_FOR` and `voiceOf` in `build.mjs`, as Sound Box does for its quips), so a quip is never taken for an instruction. The voice is part of the clip's key. With the device voice, a quip is said a little higher (`PITCH` in `speech.js`).
  - Lines queue one after another; `say(kind, text, true)` clears the queue first. An optional fourth argument, `live`, is asked when the line's turn comes, and false skips it: lines about a problem pass `asked(G.cur)` in `app.js`, so they don't pile up behind a fast answer.
  - Names the voice should say differently from how they're written go in `SAY_AS` in `lines.js`: "Twodini" is said "Toodini" (too-DEE-nee, for the Houdini pun; Kokoro stresses "Twodini" up front), "Jr." is "Junior", "Mr." is "Mister", "Plusington" is "Plussington", "Chompette" is "Chomp-ette", "Nine-ja" is "Nine-jah", Chef Eight's "Bon appe-eight!" is "Bon appa-eight!" (APP-uh, not uh-PEH), and Sevenstein's "Six, seven" gets pauses (in his monster line and his quip). The quips' puns ("Bon appe-eight", "Zeroic", "Abraca-double", "Four-ward") read right as written. Check a spelling with Kokoro's espeak phonemes before adding it (phonemizer in the Kokoro venv, run in `container`). These fixes usually come from the listen check.
  - Every line the game says lives in `js/lines.js` (`PHRASE`, monster lines, and `facts()` from `problems.js`: sums and differences within 20, the 2–12 tables and their division facts, each as the problem and as "… is …"). `app.js` only says lines from there; `scripts/lines.test.mjs` fails on any other `say()`.
  - `scripts/audio/build.mjs` (patterned on Sound Box's) records each line as one whole clip with Kokoro (`af_heart`, speed 0.95). Whole clips won a listen test against stitched numbers, which sounded choppy.
    - Clip names hash model, voice, encoding, method, speed, kind and text, so a clip never changes once made.
    - Each build reads the live `index.json` from the audio host and records only missing clips.
    - `audio.json` lists only clips that are live, so a line without one uses the device voice.
    - With `GENERATE=false` (CI without the Cloudflare token) nothing is recorded.
    - Bigger problems (Hard mode, sums over 20) aren't recorded and use the device voice.
  - The audio host is the Cloudflare Pages project `sumgeon-audio`, served at the custom domain https://sumgeon.asset-data.stream/ (like Sound Box's). Use the custom domain, not `sumgeon-audio.pages.dev`: bare pages.dev ignores byte-range requests, and Safari's `<audio>` needs them. CI's `audio-deploy` job uploads new clips; it needs the `CLOUDFLARE_API_TOKEN` secret.
  - To record locally on a Mac: `ASSET_BASE=https://sumgeon.asset-data.stream/ KOKORO=container KOKORO_DIR=<folder for the model and venv> node scripts/audio/build.mjs`. Kokoro runs in Apple's `container` (the macOS espeak wheel is broken). Then upload with `npx wrangler pages deploy _audio --project-name sumgeon-audio --branch main`.
  - **Audio sprites**: lines marked with a `sprite` in `lines.js` (today "names": the monster and hero lines) are also joined into one file per group, `s/<key>.mp3`, with a `.json` map of where each line starts. `build.mjs` builds them from the clips with ffmpeg (CI installs it), and `audio.json` lists them under `sprites`. In the game (`speech.js`) a sprite downloads and decodes with Web Audio after the first tap; until then, and if it fails, its lines play as single clips. Each line is still recorded whole, so it sounds the same.
  - **The listen check** (`listen/`, at `/sumgeon/listen/`): a grown-up page for hearing the recorded voice, patterned on Sound Box's. It plays one group of lines at a time (`GROUPS` and each line's `group` in `lines.js`): Phrases, Monsters & heroes, Add & subtract, Times & divide, Missing numbers, Coins, Two-digit, Balance Hall, Hero quips, Team-ups, Captain lines.
    - **Play/Pause** runs through the unheard lines (or the issues, or all) one after another, and a line that plays to the end unflagged counts as OK.
    - **⚑ Something's wrong** pauses, flags the line just heard with tags and a note, and Save & continue carries on.
    - Marks are per device (`sumgeon:listen`), keyed by clip key, so a re-recorded line is unheard again.
    - **Report** copies the flagged lines or opens a GitHub issue with them.
    - It reads the site's `audio.json`, or the live one when run locally.
    - It's `noindex` and nothing in the game links to it; the check enforces both.
    - It has the game's GitHub badge with the deployed commit, which `stamp.mjs` fills in. `stamp.mjs` also stamps `listen.js` and fills the page's import map, so the game modules it reads (`js/lines.js` and its imports) are the deployed ones. Unstamped, a cached old `lines.js` showed new lines as "not recorded yet".
    - Keys: space plays or pauses, F flags, R replays, ← goes back.
  - To hear new clips locally before CI uploads them (don't run wrangler): after the local recording, `_audio/` holds every clip, so point the untracked `audio.json` at it (`base` "/_audio/a/", sprite URLs "/_audio/s/…") and serve the worktree root. Both stay out of git (`.gitignore`).
  - `scripts/audio/listen-test.sh` renders the whole-vs-stitched comparison, for any future method change picked by ear.
- The game speaks: "Now entering the Sumgeon!" when you tap Enter the dungeon, monster names on arrival, "Critical hits!" at 3 in a row, the right answer after a miss ("seven plus eight is fifteen"), floor clears, and the problem's 🔊 button.
- **Instructions for a pre-reader** (the main player can't read yet): wherever the child has to choose something, the voice says what to do, in lines of about 12 words or fewer (`lines.test.mjs` checks). Lines that explain play only the first time or first few (`once(tag, times)` in `app.js`, saved per player as `told`); the rest play at the moment they matter.
  - Start screen: "Pick your hero!" on the first tap when no hero is picked (speech needs a tap first); picking says the hero's captain name line (below) and nothing after it. Enter without a hero, or Try again after a loss without one: "Tap a hero first!"
  - The first fight: "Tap your answer, then tap Hit!" (once).
  - Coin and comparing problems are read aloud as they appear (`spokenProblem`), since a pre-reader can't read "How many dimes?" or "3 + 4 □ 8". The first comparison adds "Tap the sign whose mouth opens to the greater side!" and "Both sides the same? Tap equal!"
  - Spells: "Cast a spell!", then "Draw your answer with your finger, then tap Cast!" (first 3 spells); "Try again!" after a failed read, "Use the numbers this time." when the pad comes back.
  - Losing all your hearts: "X won this round.", then "Oh no! Twodini was cursed! Pick a new hero." (`heroCursed`, per hero, in the names sprite).
  - A win: "Go deeper for tougher monsters, or play again!" (first 3 wins, not when a new stratum opens, which makes its own offer).
  - Pause: "Paused. Tap the big button to keep fighting." (first 3 times); Exit's first tap: "Tap again to leave the dungeon."
- **What traits and events mean**, said at the moment they happen:
  - A monster's trait (`TRAIT_LINE`, `traitLine` in `lines.js`), after its name, the first 2 times you meet that trait: "Watch out for lightning! A miss costs two hearts.", "Armor! Answers under ten do half damage.", and so on; a cursed digit says its digit ("Answers with a four hit double!").
  - Minustaur's charged problem: "Lightning problem!"; a miss on one: "Lightning! You lost two hearts."
  - The rescue floor: "Cursed Twodini!", then "Beat the curse to set Twodini free!" (`heroRescue`). The curse cracking: "Two more to go!", then "One more, and Twodini is free!" (`heroAlmost`). Freed: "Twodini joins your team!", then "Answers with a two bring Twodini in to help!" (`heroHelps`). Per-hero lines are in the names sprite.
  - Barks (`BARK`): at most one per hit, for what it did: "New level!" (always), or once a floor each "Split in two!", "Second wind!", "Double damage!", "Half damage!", "Power hit!". None on a hit that skipped ahead or was a backwards spell, and only the half-HP ones on the hit that says "Critical hits!".
  - A floor cleared: "You found a heart!" when one comes back, and "Next: the boss!" before the boss.

## Core rules
- Damage = the correct answer. Three correct in a row turns on crits (double damage) until a miss. A hinted answer still hits but doesn't build the streak.
- Problems come from the learning engine (`learn.js`, DESIGN.md §5), not at random:
  - Each player has a record per fact (`facts`): box 0–4, times seen and right, average answer time, last seen.
  - A right, unhinted answer moves a fact up a box (two when fast, from box 1). A miss sends it to box 0. A hinted answer changes nothing.
  - **Fluent** means right, unhinted and under `fluentTime(band.fluentMs, answer)`: 4 s in Sprout and Apprentice (counting the reading and the taps), plus 1 s for each extra digit to tap. At 3 s, about half a fluent adult's answers counted as slow.
- **Skipping ahead** (`tiers`, `probeKey`, `skipTo` in `learn.js`): each band's facts, easiest first, are cut into tiers of about 20 that stay inside a level. After two fluent answers in a row, each problem is a probe: a fact not yet learned from the tier above the first one not yet learned. **5 fluent out of the last 6 probes** (`SKIP_PROBES`, `SKIP_WINDOW`) count everything below the probe's tier as known ("You already know these. Skipping ahead!"), so one mis-tap doesn't undo it. Two slips in the window pause probing for 3 problems. Skipped facts come back as reviews.
  - **Leaps:** probes start one tier above the frontier, and each skip in a row doubles how far up they come from (1, 2, 4 tiers, `MAX_LEAP`); a slipped window drops it back to 1. With one tier per skip, a fluent adult on an iPhone took 6+ runs, since a fluent run is only about 8 Sprout problems (crits end floors in a hit or two).
  - The tally (`flowOf` in `app.js`) is per player and band, so slow coin probes on Trollar's floor don't cut short a run of fluent sums, and it carries from run to run while the game is open.
  - `node scripts/balance-sim.mjs` simulates it with real fights (monster HP by depth, crits, Quizard's missing numbers): a fluent player opens the next strata in about 3 runs, a slower one in about 5, and a learner never skips.
- **Placement:** a fact seen for the first time and answered right, fast (under the band's `fluentMs`) and unhinted is already known and goes straight to box 3 (learned), so a fluent player isn't held back.
  - Each problem is about 60% learning facts (box 0–2, box 0 favored), 25% review facts that are due (box 3 after 10 minutes, box 4 after a day), and 15% new facts from the newest open level. The monster's operation is preferred 70% of the time. The last 3 facts don't repeat.
  - A missed fact comes back 2–4 problems later.
  - **The captain's digit:** in a player's first fight (nothing beaten yet, so no Hero Moments) about 85% of problems avoid it (`CAPTAIN_HOLD`, `avoidDigitShare`; about 18% → 2% of answers), then about a third of problems prefer answers with it (`CAPTAIN_BIAS`, 0.35, `digit`/`digitShare` in `choose`; about 18% → 47%) until that captain's first Hero Moment has happened (`captainLean`, `MS.captains`), at any depth. Then problems are neutral; a new captain gets the lean again. It only narrows which facts are open; the learning, review and new shares are unchanged.
  - **Variety:** a problem is never the same kind (operation) with the same answer as either of the last two when there's another choice (`avoidAns` in `choose` and `probeKey`, as "op ans"). The same answer from a different kind (3 + 7 after 17 − 7) is fine. The teen subtraction facts all equal 10, and with Minustaur preferring − they came up in a row.
- Bands (`BANDS`) replace the prototype's operations and Easy/Medium/Hard:
  - **Sprout** (K–1st, 7 hearts): within 5 → within 10 → 10 and some more → within 20.
  - **Apprentice** (2nd–3rd, 5 hearts): within 20 → ×2, 5, 10 → ÷ → ×3, 4 → ÷ → ×6–9 → ÷ → ×÷ 11, 12.
  - A level opens when 70% of the level before is learned (box 3+). Apprentice's "within 20" level runs **alongside** (`alongside` in `BANDS`): it's open from the start and doesn't gate × 2, 5, 10, so a 3rd grader shaky on teen subtraction still gets multiplication in the first run. New facts come half from it and half from the newest level, and its facts keep coming as learning and review; the × and ÷ levels after it open in order. `node scripts/apprentice-sim.mjs` simulates it (a fluent-× but shaky-± 3rd grader, a fluent player, a learner). Strands (coins, two-digit) open theirs at 50% (`unlock`), since they're asked one floor a run. Every banded fact is one of the 633 recorded facts, so every problem has the recorded voice.
- Hints (`hints.js`, DESIGN.md §5.3) follow how classrooms teach now: ten-frames, 10 and some more, make 10, doubles (two rows of 8, the 5s make 10), doubles plus one, draw and cross out, arrays, ×2 as a double, ×10 as tens ("7 tens is 70", base-ten rods), doubling (×4 as double ×2, ×8 as double ×4), break apart (at 5 for ×6–8, at 10 for ×11 and ×12: 12 × 6 = 60 + 12), ×9 as ×10 minus a group, think multiplication.
  - Teen subtraction picks its strategy by the numbers: take away from the ones when they're enough (15 − 3: "15 is 10 and 5", and 14 − 4, 14 − 10, 20 − 1), count back to 10 then the rest when taking a little crosses ten (13 − 4, on a number line), doubles for a double (16 − 8: 8 + 8 = 16), and think addition, counting up, when the numbers are close (the answer smaller than what's taken away: 12 − 8, 17 − 15). This follows the school's curriculum guides (Missouri Learning Standards): "use a ten to subtract", counting back on a number line, doubles to add and subtract, and "use what I know about addition".
  - Two-digit subtraction takes away the tens and ones when the ones are enough (69 − 6, 69 − 26, base-ten blocks crossed out), goes back to a ten when a one-digit number crosses it (52 − 7: back to 50, then 5 more), and counts up by tens only when both numbers have tens and it crosses one (52 − 28).
  - `scripts/hints.test.mjs` runs every fact in every band through `hintFor` (before and worked) and checks every equation a hint shows is true.
  - A new fact shows its hint by itself after 3.5 s (`NEW_HINT_MS`), with 💡 there at once, so a player who knows it can answer first and get the credit. A fact being learned gets a 💡 button. A fact in review gets none.
  - After a miss, the voice says "Oops!" then the right answer ("Oops! Seven plus eight is fifteen."), and the worked example opens as a card over the game: "Oops!", the fact with its answer, the drawing and the worked line, until "Got it" or Enter. The message under the monster says "Oops!" too.
  - Hints in play show only the drawing and its words. The explanation for grown-ups (`grownups` in `hintFor`) lives on ⚙ Settings → About → **How the hints work** (its Back returns to the About tab): how the game teaches, then one card per strategy (`STRATEGIES` in `hints.js`) with the game's drawing.
- Wrong answer or timeout: the monster lunges, lose 1 of 5 hearts, and the correct answer is shown and said.
- Clearing a floor restores 1 heart (up to the band's hearts: 7 in Sprout, 5 in Apprentice).
- Monster HP = the average answer of the player's open facts (the monster's operation weighted 70%) × its `hits` value, so fights last about the same number of solves at any level. Deeper floors scale it (`depthScale` in `wings.js`): 0.8 on floor 1, rising evenly to 1.3 for the boss.
- **Coins** (`js/coins.js`, Trollar): US coins typed on the number pad, never multiple choice. Coins are a *strand* (`BANDS.coins`, `strand: true`) with its own 134 facts and six levels, asked by monsters with `strand: "coins"` whatever the Wing:
  - **Find the coin** (K, naming the coins): a shuffled pile of heads and tails, and the voice asks "How many quarters?" by itself when it appears (a pre-reader can't read the word). The count is the answer, typed into a glowing "?" under the pile ("quarters = ?", `.game.find`), so the row fits an iPhone SE. Keys `¢?q:q,d,n,p`.
  - **Each coin** (K, values): one coin, drawn big, heads or tails (`¢0,1,0,0`, `¢t0,1,0,0`), "How many cents?". The voice never names it; after a miss it says the K guide's words: "This is a dime. A dime is small and silver. It's worth ten cents."
  - Then counting (1st grade): 2 to 6 pennies, nickels and pennies, dimes, quarters (`¢q,d,n,p`), "two dimes and three pennies. How many cents?", the total is the answer, biggest first.
  - `pileOf` lays the coins out each time: sides at random, a find pile shuffled; `app.js` keeps it on the problem so the hint shows the same pile.
  - Hints: find shows that coin's two sides, then the pile with it ringed in gold; one coin shows all four with values, then that coin's two sides; counting labels each value and counts on from the biggest.
  - Heads are traced from public-domain US Mint photos (see the README). Backs are drawn from simple shapes (`BACKS`): the penny's Union Shield, the nickel's Monticello, the dime's torch and branches, the quarter's classic eagle (the K guide names it; newer quarters vary too much to pick one).
- **Two-digit + and − within 100** (`js/twodigit.js`, Haberhasher, 2nd grade): a strand (`BANDS.place`) in seven levels: add tens, add ones, add tens and ones, add and regroup, subtract tens, subtract without regrouping, subtract and regroup. Each level is a fixed sample (200 facts in all), so 70% of a level can be learned and every problem is recorded (both orders of a sum). Hints: base-ten blocks with "tens and ones" for adding; tens crossed out, or counting up on an open number line (to the next ten, by tens, then the rest) for subtracting. It's a strand rather than levels in Apprentice so it doesn't lock multiplication for players already there.
- **The Balance Hall** (`js/balance.js`, K–2nd): the `balance` band, 120 fixed problems in three levels (compare and balance to 10; sums on both sides; compare to 100), each level with both kinds, opening at 50%.
  - **Comparing** (Chompers, op `○`): "3 + 4 ○ 8". The answer is the symbol, typed on **< = > keys** that take the number pad's place (`padUI`), three rows tall so nothing moves; on a keyboard `<`, `=`, `>` (or `,` and `.`). It's a math symbol typed like a digit, not multiple choice. A right answer hits for the **bigger number** (Chompers eats it), and that number's digits fly.
  - **Balancing** (the Equal Twins, op `=`): "3 + 4 = □ + 5", "7 = □ + 2". The hidden number is the answer and the damage.
  - Hints: dot rows to line up (to 10, and sums), tens then ones (to 100), and a balance scale ("Both sides are the same. 3 + 4 = 7, so □ + 5 = 7. 7 − 5 = ?").
  - Spoken: "Compare three plus four and eight.", "three plus four is less than eight", "three plus four equals what plus five".
- **Missing-number problems** (`js/missing.js`): a fact with one number hidden, like `3 + □ = 7`. The answer and the damage are the hidden number. The □ shows as a glowing "?" that fills as you type (the answer box hides), and the hint is the inverse fact's (3 + □ = 7 is 7 − 3). They use the fact's own record. Quizard asks only these; other monsters ask 15% of review facts (box 3+) this way. Spoken as "three plus what is seven", recorded for every fact.

## Wings, monsters and heroes
Runs happen in Wings (`js/wings.js`, DESIGN.md §4), called **strata** (one **stratum**) wherever the game shows the word; the code keeps "wing". Each Wing asks one band's facts and has a monster pool, a rescue floor (floor 3) and a boss:

| Wing | Band | Floors | Boss |
|---|---|---|---|
| The Counting Cellar | Sprout | Plusquito, Minustaur, rescue, Quizard, Trollar | Make-Ten Golem |
| The Balance Hall | Balance | Chompers, Equal Twins, rescue, Chompers, pool | The Unknown |
| The Tables Tower | Apprentice | Timesaur, Divvy, rescue, Starbot, Haberhasher, pool | Sigma Rex |

- **Depth** (`depthHP`, `deepest` in `wings.js`): beating a Wing's boss opens its next depth, saved as `wings[id].depth` (the deepest reached). The win card's main button is **Go deeper** (depth + 1), with Play again (same depth) and Menu; a loss offers Try again. "Enter the dungeon" starts at the deepest depth.
- **A new stratum unlocked** (`end` in `app.js`): when a run opens a stratum, the end card shows "🔓 New stratum unlocked!" with its name (both, when the Cellar opens the Hall and the Tower), the voice says "New stratum unlocked!" and "The … is open!", and the main button is **Enter the …** (the easiest one opened, at depth 1), with Go deeper below it.
  - Each depth is tougher: HP × (1 + 0.15 per depth).
  - Every floor but the rescue floor and the boss is drawn from the pool, never the same monster twice in a row.
  - More of the newest problems: `choose`'s fresh share goes from 15% to 35%.
  - The room darkens (`--murk`, 8% per depth up to 48%).
  - Shown as "Depth 2 · Floor 1 / 6" and on the Wing map, and said as "Depth two!" (recorded to 20).
  - It keeps runs from feeling the same while the next Wing waits on mastery.
- **The depth map** (`wingsHTML`, `depthTrack`, `.strata`): the start screen shows the strata as rock layers under a grassy surface, each in its own texture. Each open layer has a shaft of its depths going down: cleared (gold), "you are here" (coral), and the ones below. It starts at `MAP_DEPTHS` (5) rows and grows as you go deeper; after 8 rows the early cleared ones fold into one. Tap a layer to pick it; double-tap it to enter (a second tap on the same layer within 450 ms is Enter). Depth never opens the next strata; only mastery does.
- **The dive** (`diveUI`, `#dive`): during a fight, the same shaft runs down the left edge of the monster's box, every depth from 1 to two below the deepest. It scrolls (swipe it), opening with this run's depth in the middle, and fades at the ends. On phones it's dots only, and tapping one shows its score in a bubble ("Depth 3: ★ 12 of 18"); on iPad and desktop it shows the depth numbers and scores.
- **Depth scores**: the most stars earned in one run at a depth, saved as `wings[id].depthStars[depth]` (out of 3 per floor: 18 in the Cellar and Hall, 21 in the Tower), shown on the dive and the depth map.
- **Colors**: each stratum has its own palette to go with its wall (`body[data-stratum]` in `styles.css`: `--bg`, `--panel`, `--line`, `--btn`, `--btn2`, `--edge`, `--muted`, `--dark`): warm browns for the Cellar, blue-slate for the Hall, stone grey for the Tower. Gold and coral stay the accents. Use these variables, not fixed colors, for new UI.
- **Walls**: each stratum has a tiling wall (inline SVG in `styles.css`: `--wall-cellar` bricks, `--wall-hall` marble tiles, `--wall-tower` big stone blocks), behind the monster in a fight (`data-stratum` on `.game`, set by `newRun`) and on its map layer. The Tables Tower is a tower that goes down.
- A Wing opens when the Wing it comes `after` has its boss beaten and 60% of its facts learned: the Cellar opens both the Hall and the Tower. The band a player starts in (`st.start`) opens every Wing at that grade or below (`GRADE` in `wings.js`), so starting in Apprentice opens all three.
- Per player, progress is saved under `wings`: `{ [wingId]: { boss: wins, best: floors, stars: [best stars per floor] } }`.
- **Stars** (`floorStars` in `wings.js`, DESIGN.md §6.1): each floor awards ★ cleared, ★ no hearts lost on it, ★ all fast: every answer on it right, quick (under the band's `fluentMs`) and without a hint. A short floor can earn all three (a streak of 5 couldn't be reached on a 3-problem floor). The floor-cleared and win cards show them, and the Wing map shows each Wing's total.
- Sevenstein and Octoloop aren't regular floors any more: they're cursed digits (7, and 8, whose cursed form is Octoloop).
- **Monsters & Heroes** (📖 on the pause screen; `bookPage` in `app.js`, `js/bestiary.js`): every Wing's monsters, met or still a silhouette, with their trait, times beaten, and a mastery ring for the share of their kind of math learned (their operation's facts in their Wing's band; gold outline when full); then the ten heroes, rescued or still cursed. Monsters met and beaten are saved per player under `bestiary`: `{ [name]: { met, beaten } }` (cursed digits belong to the Heroes half).
- Cards over the game (`show(html, kind)`) open at the top and focus their main button (the last in `.btns`) without scrolling to it.
  - `"page"` (the default: the start screen, Settings, Monsters & Heroes, help, a run's end) fills a phone's screen, with its buttons docked full-width at the bottom; on iPad and desktop it's a centered card.
  - `"float"` (a floor cleared, a rescue, the Oops card) floats over the game as a centered card on every size. (Not "pop": that's the damage number's class.)
- The battle header is just the title and floor (sound is the device's volume; Settings has the on/off switches). ⏸ sits at the right of the hero-and-hearts row (or Escape): the pause card stops the clock mid-problem and offers Keep fighting (the same problem, with the time that was left), 📖 Monsters & Heroes, ⚙ Settings (opening on Game, without the Players tab, since switching would end the run) and Exit the dungeon (a second tap confirms).
- The start screen has ⚙ Settings by the title (no speaker buttons outside the problem: volume is the device's keys), then your hero, the Wings, and Enter docked at the bottom. Short phones drop the tagline so it all fits.
- The start screen shows your hero as one line with "Change", which opens the grid of ten (the first time, the grid shows by itself). The run's end card uses the same line.
- Settings has tabs (`settings(paused, tab)`, `wireTabs`, `aboutHTML` in `app.js`), each an icon over a short word for pre-readers: 👥 **Players** (player rows; left out when paused), 🎨 **Game** (the chalk colors in one row, on/off switches for sound effects and voice) and ℹ️ **About** ("How the hints work ›", the credits from the README's License section, and the footer badges). It opens on Players from the start screen and on Game from the pause screen; the last tab isn't remembered. The tabs follow the WAI-ARIA tabs pattern (`role="tablist"`/`tab`/`tabpanel`, `aria-selected`, roving tabindex, ←/→/Home/End). Done goes back to where Settings was opened.
- **Looks** (`LOOKS`, `lookOf` in `monsters.js`): each regular monster has four more looks with their own fun names (Minustaur's Mom, King Minus, Baby Minustaur, Professor Minustaur). A look is the same symbol drawing with extras from a kit placed on its face and head (`ANCHOR`, `KIT`: crown, bow, lashes, glasses, monocle, sunglasses, eyepatch, top hat, nightcap with sleepy eyes, headband, scarf, bow tie, medal, spiral eyes, sparkles, or drawn smaller). A look can be "he" or "she" (the third item in `LOOKS`), and its lines say "his" or "her" (Minustaur's Mom loses her footing). It keeps its monster's trait and math (`m.base`; `traits.js` checks `kind(m)`). Depth 1 has the originals; below it each floor's look is fixed per stratum, depth and floor (`dressed` in `wings.js`). Meeting a look counts as meeting its monster, and Monsters & Heroes shows each monster's looks found. Every look's lines are recorded. Bosses and cursed digits have no looks.
- **Spell casting** (`castSpell` and friends in `app.js`, `js/sigil.js`):
  - **When:** about 1 problem in 6 (`SPELL_SHARE`), on touch screens only (`any-pointer: coarse`; drawing with a mouse isn't writing): a learned fact with a one-digit answer (`spellKey` in `learn.js`). It's rolled before skip-ahead probing, since a fluent player probes nearly every problem and otherwise never got a spell. Not on Quizard's floor or a missed fact coming back. `?spells` makes every single-digit problem a spell, for testing.
  - **The pad:** the number pad becomes a glowing drawing pad in the same space (`padUI("spell")`), with Clear and Cast. The voice says "Cast a spell!".
  - **Reading:** `sigil.js` is a $P point-cloud recognizer on the device (no machine learning, no server), 32 points per cloud.
    - **Shapes** (`SHAPES`), several per digit for how kids and grown-ups write them: open and closed 4, each also with a high crossbar and a long stem, and an open 4 whose bar curls up; 7 plain, with a crossbar, or with its bar slanted up; 1 with or without a flag and base; 9 straight, curly, with a small head, or with a pointed head and a stem starting above it (slanted or upright); 2 with or without a loop; 3 curly, flat-topped, with a z on top, or with a deep middle point that comes back to the left edge; 5 in one stroke (also wide, from the top right); 6 curled, a tall stem into a loop, or one big lemon-shaped loop from the top right; 8 as a figure eight, two circles, one stroke from the top right, or slanted with a thin top loop; 9 also like a "g", with a hooked tail. The kids' shapes (deep-middle 3, lemon 6, slanted 8, g-like 9) are drawn from the drawer-2 fixtures, and each fixture still reads unclear-not-wrong without its shape.
    - **No squared-U 4**, on purpose: a kindergartner (drawer-2) copied Bungee's 4 as a U, and the game teaches the school 4 instead of learning it (a poor match, below).
    - **Variants** (`VARIANTS`): $P scales evenly, so a slanted or stretched digit is a different cloud. Every shape is also a template slanted about 14° each way, narrower and wider (375 templates in all).
    - **Mirrors**: every shape's mirror is a template that means reversed (not for 0, 8 or a plain 1; the mirror of a one-stroke 8 is the same digit begun at the top left).
    - **Speed**: a quick pass (one greedy match, one way) keeps the closest 24 templates and the closest 3 of each digit for the full $P match, about 10 ms a read in Node.
    - A read is **clear** when its fit is at least `CLEAR.fit` and it's ahead of the next digit by `CLEAR.margin` (15%), or `CLEAR.reversed` (20%) when it reads as backwards: every mirror is a template too, so a backwards 9 sits close to a backwards 4 or 7, and most drawings face the right way.
    - It counts as **reversed** only when the mirror is clearly the better match (`REVERSED_MARGIN`), so a wobbly 1 gets the benefit of the doubt.
  - **Outcomes** (`judge(read, answer)` in `sigil.js`: the game knows the answer, so a drawing only has to look like it):
    - **Wrong:** only a clear read of another digit. It's checked first, so a clear read is never overruled.
    - **Backwards:** a clear read of the answer facing the wrong way: half damage, the digit shown the right way round with an arrow, and "Your 3 is facing backwards. It faces this way."
    - **A good match** (`hit`): the answer is the best digit, facing the right way, fit ≥ `ACCEPT.good` (0.5) and clear or close to it (margin ≥ `ACCEPT.near`, 5%). It hits, and the drawing is saved as one of the player's own templates (the last 3 per digit), unless the built-in templates alone read it clearly as another digit.
    - **A poor match** (`show`): the answer is the best digit, or its own best fit (facing the right way) is within `ACCEPT.gap` (0.05) of the best digit's, at fit ≥ `ACCEPT.floor` (0.25), but it isn't a good match. The math was right, so it hits for full damage, but it isn't learned: the school-style digit (`handwriting.js`) glows over the dimmed drawing, the message says "Here's how to write it", and the voice says "Here's how to write a four." (`howToWriteLine`, recorded for 0–9). So a kid's odd shape gets taught, not kept.
    - **Anything else:** "Incantation failed!", no heart lost, try again. After two, the number pad comes back.
    - The numbers come from the fixtures: every real drawing fits its digit at 0.6 or better except drawer-2's squared-U 4 (0.27), which lands in "poor". A gap of 0.05 is about a third of the clear margin; it accepts some drawings for an answer they aren't (they hit, and show the right digit), never a clear read.
  - **Kept out of learning:** a spell changes no fact record, timing, placement, skipping or the "all fast" star.
  - **Saved** per player as `spells`: `{ templates, reversed: { digit: count }, cast }`.
  - **The spell check** (`spell/`, at `/sumgeon/spell/`): a grown-up page, built like the listen check, in two modes.
    - **Try it:** draw any digit and see the read, its fit and margin, and whether it's reversed, with or without a player's learned handwriting. **Expecting** picks an answer (or none) and shows what the game would do: hit (and learn it), hit and show how to write it, backwards, wrong, or try again. It also shows each player's backwards counts by digit.
    - **Record** (`#record`): collects real kids' handwriting to test the reader on. Pick who's drawing (the device's players, or "Someone else"), and it asks for 0 to 9 in order, one very big digit at a time, drawn in plain school-style handwriting (`handwriting.js`, gold, round caps) rather than the Bungee font, whose quirks kids copy (its 1's long flag and base, its squared-U 4), with big Redo, Skip and Next (saves it) buttons and a small "3 of 10". It says nothing and never shows the read, so a wrong guess can't put a kid off. After 9 it offers another round.
    - **A recording** (`js/drawings.js` has the format): the digit asked, the strokes as `{ x, y, t }` (CSS px; `t` in ms since the drawing's first touch), the canvas size, device pixel ratio, pointer type, user agent, who, when, and what the reader made of it then (`read.builtin`, and `read.player` with the player's learned handwriting).
    - **Kept** in localStorage under `sumgeon:drawings` (a page-level key, like the listen check's), with how far each drawer got, until a grown-up deletes them (a second tap confirms), so a kid can stop and carry on.
    - **Share as a zip** builds a stored (uncompressed) zip in the page (`js/zip.js`, with CRC-32; `scripts/zip.test.mjs`): `drawings.json`, a PNG of each drawing (`3-maya-1.png`, white on dark) and `README.txt`. It's built synchronously inside the tap, so `navigator.share({ files })` still counts as the user's (iOS Safari's share sheet: AirDrop, Messages, Mail, Save to Files); where files can't be shared, it downloads instead. Afterwards it offers to delete the recordings, never on its own.
    - **To fixtures:** `node scripts/drawings-to-fixtures.mjs <zip or drawings.json>` adds them to `scripts/sigil-fixtures.json` (`{ format, fixtures: [{ id, digit, who, width, height, strokes: [[[x, y], …], …], read }] }`), once each by id, with each name replaced by a plain label (`drawer-1`, `drawer-2`, …, not a hash a name could be guessed from) so names stay out of the repo.
    - `scripts/sigil.test.mjs` tests every template, its mirror, messy copies and a scribble, and every fixture: none may read clearly as another digit (unclear is counted, not failed). The `shot-` fixtures are a grown-up's ordinary handwriting traced from iPhone screenshots of the spell check; each must read clearly and right, and its mirror as backwards. Slanted, stretched and wobbly variants of them and of every shape must never read clearly as another digit (at the fixed seed, reseeded just before them so a new shape doesn't reshuffle them; `SIGIL_SEED=<n>` tries another). The kids' fixtures must read at least as well as when recorded, and `judge` must hit with each knowing its answer (the squared-U 4 as a poor match, not learned); a clear read is never accepted for another answer, and an unclear one is never wrong. The school-style digits must read clearly as themselves.
- **Boss roars** (`roarSoon` in `app.js`, `roar` in `sfx.js`): every 9–15 s of a boss fight, while you're working on a problem (never during an attack, a card, a hint or the pause), the boss growls (a low, wobbling saw tone over a rumble) and rears up and shakes while the room flickers darker. With reduced motion it only growls.
- **Hero Moments** (DESIGN.md §8.4; rules in `js/moments.js`, the show in `js/slowmo.js`, wired in `app.js` `momentFor`/`heroMoment`): now and then a hero in your answer gets a slow-motion close-up and a quip before it strikes.
  - **When** (`decide`): a right, unhinted answer with a team hero's digit, never in a player's first fight (nothing beaten yet), and not on a spell's backwards or poor-match hit (a good spell is fine). 8% a qualifying hit (`CHANCE`), plus 4% for each that rolled without one (`BUILD`, saved as `dry`), back to 8% after one. None in the 6 problems after one (`REST`), at most 2 a floor (`PER_FLOOR`). A different hero from last time when the answer has more than one.
  - **Always** on a freed hero's debut (`joined`, from `cleared` in `app.js`: their first qualifying answer after joining) and on the blow that finishes a boss ("Final answer!", by the captain when no hero's digit is in the answer). A moment on the hit that turns crits on says "Critical math!".
  - **Damage:** a rescued hero in the moment adds +25% (each, in a team-up); otherwise it's unchanged. The hero takes the slow-motion turn; the answer's other digits fly at the snap.
  - **Quips** (`QUIPS`) come from a shuffled deck per hero, saved per player as `moments` (`decks`, `heard`, `debut`, `dry`, `last`, `captains`, `named`), so none repeats until all are heard. Monsters & Heroes shows "Quips: n of N" on each hero.
  - **The show** (`playMoment`, about 2 s): wind-down (time drags to ¼ speed, the room dims), close-up (the hero swells toward the camera, a slight zoom on `.game`, blur at the edges), freeze (the quip in a bubble, said with `say("h", …, true)`, a heartbeat; it holds 1–2.4 s for the voice), snap (double speed, the hero's own move, `MOVES`), then the hit (a bigger impact, a screen shake, then the usual damage number). It's a fixed overlay (`.hm`, its styles injected by `slowmo.js`), so it works in every layout. With reduced motion: the hero, the bubble and the hit. Input waits (`G.busy`), so roars, hints and the pause wait too.
  - **The quip's sound** (`playHero` in `speech.js`): kind "h" lines (quips, team-ups, captain lines) play through Web Audio rather than an `<audio>` element, louder (`HERO_GAIN` 2.2 into a limiter; iOS caps an `<audio>` element at full volume) with a short arena echo (`HERO_ECHO` 0.28), so Bella rings out over the moment's sounds. `?herogain=<n>` and `?heroecho=<0..1>` try other values. If it can't (no context, a failed decode) it falls back to the plain clip, then the device voice.
  - **Sound** (`sfx.js`): `tapeStop`, `heartbeat`, `swell` (a reverse cymbal), `whip`, `slam` (`slam(true)`: a team-up's bigger landing), `scratch` (a record scratch, when the moment's quip has to cut the voice off mid-line or drop queued lines: `speaking()` and `cutOff` in `speech.js`, run by `playMoment`'s `before` hook before the moment starts, so it's heard on its own; the voice is stopped first and the scratch starts `SCRATCH_AT` later, 120 ms by default, because a paused `<audio>` clip keeps sounding a moment on a phone; `?scratch=<ms>` tries another value, and the review page's "Talking over" starts the voice before each Replay to hear it), and `move(d)`, each hero's own sound at the hit, after their move (`MOVE`): Zeroic a whoosh into a pow, Onesie a pillow fwump, Twodini a sparkle and a pop, Threasure Hunter a lantern shimmer, Sir Fourtress a shield clang, High Five a hand-clap smack, Sixlock Holmes a glint ding, Sevenstein a stomp and rumble, Chef Eight a sizzle and a plate clink, Nine-ja a smoke poof and a slash (a team-up plays both). All respect the sound-effects switch.
  - **Team-ups** (DESIGN.md §8.4): a moment by chance on an answer with two different team heroes' digits is a team-up half the time (`TEAMUP`), so no extra moments. `decide` returns `partner` too: `hero` is the left (tens) and `partner` the right, in the answer's digit order; with three or more digits, two different heroes. Doubles (one hero), debuts, captains' first moments and boss finishes stay solo.
    - Lines (kind "h", in Bella, the listen check's "Team-ups" group; no per-pair lines): `TEAM_LINES` from their own deck (key "team" in `decks`), or, when the answer is exactly one of `TEAM_NUMBERS` (10, 12, 13, 25, 36, 49, 64, 67, 81), that number's line. 67 is Sevenstein's own "Six, seven!", the same line and clip (`spokenLines` dedupes). "Critical math!" on the crit hit, unless the number has a line.
    - The show (`playTeamUp` in `slowmo.js`): both swell in side by side, each a little smaller than a solo close-up so they fit an iPhone SE, under one bubble; at the snap they whip out to opposite sides and in, crossing at the monster (a second `whip` a beat later), and land with `slam(true)` and a bigger shake. Reduced motion: both heroes, the bubble and the hit. In `app.js` the answer's other digits (minus both heroes') fly at the snap.
  - **Captain lines** (DESIGN.md §8.4, §6.6; kind "h", in Bella, the listen check's "Captain lines" group):
    - In a fight, shared lines only (`CAPTAIN_LINES`: "Captain's orders!", "Leading digit, leading the charge!", "The captain always counts!", "First in line, first to strike!", "Power hit, captain style!"), from their own deck (key "captain"): a solo moment by chance for the captain is a captain line half the time (`CAPTAIN`), the hero's own quip otherwise.
    - A captain's first moment (`why: "captain"`): their first qualifying hit with their digit, past the first fight, is always a moment, with a shared line. Once per captain (saved as `captains` in `moments`), so a new captain gets one. A rescued hero's debut and a boss finish come first; it counts toward `REST` and `PER_FLOOR`.
    - On picking a captain (`wireCaptain` in `app.js`: the start screen, the end card, a free pick), the hero says a name line (`nameLine`, `captainNames`) in place of the plain name, and nothing after it: "Captain <name>, reporting for duty!", "…at your service!", "Captain <name> leads the charge!" or "Make way for Captain <name>!". The style rotates across all picks, whichever hero (a shared deck, key "style"), so tapping through heroes varies; the very first captain a player picks reports for duty (picked heroes saved as `named`).
  - `?moments` makes every qualifying hit a moment, for testing. `?teamup` does too, and makes every one that can be a team-up a team-up.
  - `node -e` with `simulate` (or the review page) runs the rarity simulator: with a captain and two rescued heroes, about one moment every 2.8 floors, 2 a run (one is the boss finish); it counts `teamups` too (about 1 in 20 chance moments with captain 5 and 0, 1 in the Cellar, where few answers have two heroes), and `captainLines` (about 1 in 15 there). `scripts/moments.test.mjs` tests the rules, the decks, team-ups, captain lines and the rate.
  - **The review page** (`moments/`, at `/sumgeon/moments/`), built like the listen check: pick a hero, a quip and a monster in any stratum's colors and wall, and play the real moment (the same `slowmo.js`, sounds and recorded quip). **Team-up with** picks a second hero (or None); the quip menu has a Team-ups group (its values start "T|", since "Six, seven!" is in both), and a number's line brings its own pair; a Captain group has the hero's name lines and the shared captain lines. Marks for a team-up are keyed "1+5|line". Replay, Play all (every hero's quips, then the team-ups: each general line with a sample pair, each number's line with its own digits; then the five shared captain lines with sample heroes and each hero's four name lines), Step through the frames, ½× or 1×, reduced motion. **⚑ Something's wrong** flags it (Wording, Voice, Timing, Art, and a note); unflagged counts as fine; marks per device under `sumgeon:moments`; **Report** copies them or opens a GitHub issue. A **Sounds** board plays every sound effect on its own, grouped (Hero Moment, hero moves, monsters, the fight), each with what it's meant to be, for checking by ear. A rarity simulator shows moments per floor and run, and how often each hero and quip comes up. `noindex`, unlinked, and stamped (`stamp.mjs` also stamps its `../styles.css`, which it loads for the walls).

- **Digit heroes** (`js/heroes.js`, DESIGN.md §6.6): Zeroic (0), Onesie, Twodini, Threasure Hunter, Sir Fourtress, High Five, Sixlock Holmes, Sevenstein, Chef Eight, Nine-ja (9).
  - The start screen asks for a hero first, and the end-of-run card offers the hero picker again. The first pick can be any of the ten, and so can any pick while the dungeon has no progress yet (nothing played, say after a reset, and the team is just your own hero; `freePick(team, fresh)`). After that, any hero on the team (picked or rescued) can lead a run. **Losing all your hearts curses the hero who led the run** (`curseCaptain` in `heroes.js`): it leaves the team, to be rescued again on a rescue floor, and the end card asks who leads next from the rest of the team, or from all ten when nobody is left (`freePick`, `pickHero`). Saved under `heroes`: `{ captain, color, rescued: [digits] }`.
  - The start screen holds only the hero, the Wings, "Enter the dungeon" and a ⚙ Settings link. Settings (as in Sound Box) holds Players (names optional, "Player 2" when blank), chalk color and sounds, and About.

- Monsters and heroes are inline SVG drawn from simple shapes (no fonts), using the `solid()` and `line()` helpers. Each helper draws a dark outline, then a color fill, then a white sheen gradient.

## Settings
- Band: Sprout or Apprentice (per player). Changing band starts a fresh dungeon.
- No timer, ever (settled 2026-11-25): speed is used only to judge fluency (`fluentTime`: placement, skipping ahead, box jumps) and for the ★ all-fast star, and never changes damage. A saved `timer` setting from the prototype is ignored.
- Sound effects and voice.
- Settings and best floor are saved per player (see Players and saving).

## Publishing
- Public repo `jbtule/sumgeon`. Pushing to `main` deploys to GitHub Pages at https://tools.tuley.name/sumgeon/ through `.github/workflows/ci.yml`. `scripts/stamp.mjs` builds `_site/` (Sound Box's pattern): it copies the files in `SITE`, adds `?v=<short sha>` to each local file the page loads (`STAMPED`), and fills in the footer's GitHub badge with the short sha so you can see what's deployed (locally it reads "dev"). Add new site files to `SITE`, and anything the page loads to `STAMPED`.
- **Icon**: Plusquito on the Cellar's bricks. `design/icon/` holds the source (see its README): `make.mjs` draws the layers and `favicon.svg`, and `site.py` renders `apple-touch-icon.png` and the manifest's `icon-192.png`/`icon-512.png` from the Icon Composer document. `manifest.webmanifest` (standalone, the Cellar's brown) and the icons are stamped like the page's other files.
- **Update checking** (`checkUpdate` in `app.js`): `stamp.mjs` writes `version.json` (`{ sha }`). The game asks for it, uncached, when it wakes up (visibilitychange, focus, pageshow, so also the Home Screen app coming back) and every 15 minutes. If a different version is deployed, it reloads at the next safe moment: the start screen, never mid-run (Settings and Monsters & Heroes wait too). The reload adds `?v=<sha>` to the address so the browser can't reuse its cached old page, and it tries once per version (`sumgeon:update` in sessionStorage), so a stale cache can't loop. Locally the badge reads "dev" and nothing is checked.
- Workflows must pass `zizmor .`: actions pinned to a SHA, minimal `permissions`, and `persist-credentials: false`. CI runs zizmor too.
